# Creality K1 / K1C / K1 Max

A K1 runs everything as **root** from `/usr/data`, starts services from `/etc/init.d`,
and normally has no `sudo`, `systemctl`, `git`, `bash` or Python venv. The plugin
modules run as root without changes, and **no installer refuses root**. Two ways to
install:

1. **Standard installer as root** (same transaction/backup/uninstall logic as on any
   host). On a host without systemd it skips the automatic restart and prints the
   manual command instead of failing:

   ```sh
   cd /usr/data/accel_homing
   python3 installer.py --no-update-manager --skip-plotting --dry-run
   python3 installer.py --no-update-manager --skip-plotting
   ```

   `--no-update-manager` is needed when there is no `git` clone/Moonraker updater;
   `--skip-plotting` is needed when Klippy's Python has no venv/matplotlib (see
   below). Uninstall with `python3 installer.py --no-update-manager --skip-plotting --uninstall`.
   (`install.sh` works too when `bash` is available.)

2. **Simple K1 installer** (`install_k1.sh`, plain `/bin/sh`, auto-detects the running
   Klippy and restarts through `/etc/init.d`), described next. Use one method per
   installation, not both.

## Prerequisites

- Root SSH access and a working Klipper with a configured accelerometer
  (`[adxl345]`). Stock K1 firmware or a Klipper installed by a helper script both
  work as long as `klippy/klippy.py` exists.
- `python3` (already present, Klipper uses it).
- The plugin must be loadable by that Klipper. The installer warns when
  `klippy/mcu.py` has no `TriggerDispatch` or the ADXL driver offers neither
  `batch_bulk` nor `api_dump`; an old vendor fork may refuse to load the plugin
  regardless of the installer (see [compatibility](COMPATIBILITY.md)).

## Install with install_k1.sh

Copy the checkout to persistent storage (`/usr/data`), for example by unpacking the
ZIP or with `git` if you have it:

```sh
cd /usr/data
git clone https://github.com/DeadLama99/accel_homing.git     # or unpack the ZIP here
sh /usr/data/accel_homing/install_k1.sh --dry-run          # shows the plan, writes nothing
sh /usr/data/accel_homing/install_k1.sh                    # installs, asks before restarting
```

Keep the checkout in place: the installed modules are symlinks into it. Use
`--copy` to copy the files instead if the file system refuses symlinks.

The installer auto-detects the running Klippy (`/proc`), `printer.cfg` and the init
script. Override with `--klipper-path`, `--config`, `--init-script`, and pick the
sensor with `--accel-chip adxl345`. `--axes x` or `--axes y` installs one axis.

What it changes (all edits are tagged, originals are copied to
`.accel_homing_backups/` beside `printer.cfg`):

- links the modules into `klippy/extras`,
- sets `endstop_pin: accel_homing:x` / `accel_homing:y` and
  `homing_retract_dist: 0` in `[stepper_x]` / `[stepper_y]`,
- comments `diag_pin`, `diag0_pin`, `diag1_pin`, `home_current` in the matching
  `[tmcXXXX stepper_x|y]` sections and `min_home_dist`, `homing_accel` in the stepper,
- adds `[include accel_homing.cfg]` and creates that file with `[accel_homing]`,
- restarts Klipper with `/etc/init.d/S55klipper_service restart` after asking.
  Use `--no-restart` to do it yourself, `--yes` to skip the question.

Stepper and TMC sections in files included from `printer.cfg` (for example
`sensorless.cfg`) are found and edited in place.

## Uninstall

```sh
sh /usr/data/accel_homing/uninstall_k1.sh
```

This reverses only the tagged edits, removes the module links and the generated
`accel_homing.cfg`, and keeps everything else in `printer.cfg` (including changes
SAVE_CONFIG wrote later). Saved `[accel_homing_model ...]` blocks are removed because
Klipper rejects unknown sections; use `--keep-model` only if you reinstall right away.

## Charts and calibration need matplotlib

Ordinary `G28` homing does not need plotting. `ACCEL_HOMING_CALIBRATE`, `_CHARTS`,
`_ACCURACY`, `_CALIBRATE_NOISE` and `_TROUBLESHOOT` render PNGs and abort at their
preflight, before any movement, when Klippy's Python cannot import `matplotlib` and
`numpy`. The installer reports whether Klippy's Python can import them. Check that on
your system; if they are missing, expect these commands to refuse.

Without them, set thresholds by hand in `accel_homing.cfg` and validate carefully
with the printer supervised and an emergency stop within reach:

```ini
[accel_homing]
accel_chip: auto
x_threshold: 3.0
y_threshold: 3.0
```

Change values at runtime with `SET_ACCEL_HOMING AXIS=X THRESHOLD=3` while testing, and
write the final value into the file. Start high enough to avoid false triggers and
lower it stepwise; see [configuration](CONFIGURATION.md#thresholds-and-saved-models).
The default generic threshold is 8 g, which may be too insensitive for a K1.

## Notes

- Moonraker's update manager entry from the standard installer is not created; update
  by replacing the checkout and running `install_k1.sh` again (it is idempotent, and
  Klipper must be restarted after module code changes).
- The K1 is CoreXY with the accelerometer on the toolhead, so the sensor moves with
  both X and Y, as the plugin requires. Whether impacts are detected reliably is a
  mechanical question; see [compatibility](COMPATIBILITY.md#sensors).
- This installer was verified against a synthetic K1-style directory tree, not on
  physical hardware.
